# C++ Coding Standards & Design Principles
C++コードの作成および変更時には、以下の設計原則を厳格に遵守してください。

## 1. コア設計原則（アーキテクチャルール）

AIにコードを生成させる際は、以下の原則をデフォルトの振る舞いとして強制します。

### 1.1 完全コンストラクタとガード節（生焼けオブジェクトの禁止）
*   **ルール:** すべてのドメインオブジェクトやクラスは、初期化（インスタンス化）された時点で完全に有効な状態を持っていなければなりません。
*   **AIへの指示:**
    *   必須となる属性はすべてコンストラクタで受け取ること。
    *   引数なしのデフォルトコンストラクタで空のインスタンスを作り、後からSetterで値を詰め込む実装（生焼けオブジェクト）は禁止する。
    *   コンストラクタの先頭には必ず**ガード節（Guard Clauses）**を配置し、不正な値が渡された場合は即座にドメイン例外をスローさせること。

### 1.2 デフォルト不変（イミュータビリティ）の担保
*   **ルール:** 一度設定された変数の値や、オブジェクトの内部状態を変更してはなりません（破壊的代入の禁止）。副作用を排除し、状態変化の予測可能性を高めます。
*   **AIへの指示:**
    *   各言語の不変修飾子（Javaの`final`、TypeScriptの`readonly`、C++の`const`など）をデフォルトで使用すること。
    *   状態を変更する必要がある場合は、既存のオブジェクトを書き換えるのではなく、更新された値を持つ新しいインスタンスを生成して返すこと。

### 1.3 値オブジェクト（Value Object）の活用
*   **ルール:** 金額、数量、メールアドレスなどのドメインの概念を、単なる数値や文字列（プリミティブ型）のまま扱ってはなりません（プリミティブ型執着の禁止）。
*   **AIへの指示:**
    *   関連する値と、その値に紐づくバリデーションルールや計算ロジックをカプセル化した「値オブジェクト（専用のクラス）」を作成し、それを利用すること。

### 1.4 ファーストクラスコレクション
*   **ルール:** `List`や`Map`、`Array`などの生のコレクション型をアプリケーション層に露出させず、操作ロジックが分散するのを防ぎます。
*   **AIへの指示:**
    *   コレクションを唯一のインスタンス変数として持つ専用のクラス（ファーストクラスコレクション）を作成すること。
    *   外部への公開は、読み取り専用のビューや防御的コピーを返すメソッドのみに限定すること。

### 1.5 入力・処理・出力（IPO）の分離と単一責任（SRP）
*   **ルール:** 「データの取得（入力）」「ビジネスルール（処理）」「結果の反映・保存（出力）」を明確に分けます。変更の理由（変更圧力）が異なるものを混ぜてはいけません。
*   **AIへの指示:**
    *   1つの関数やクラスにIPOを混在させないこと。
    *   「変更のまとまり」を意識し、同じ理由で変更されるものは凝集させ、違う理由で変更されるものは分離（クラス抽出）すること。

## 2. 回避すべきアンチパターン（コードスメル）

AIによるコード生成時、以下の構造が含まれていた場合は自動的にリファクタリングの対象とします。

*   **❌ 多重ネストの禁止:** `if-else`の深いネストを避け、早期リターン（Early Return）を用いて処理の経路を平坦にすること。
*   **❌ フラグ引数の禁止:** 関数の引数に真偽値（`boolean`）を渡し、内部で処理を分岐させるのは単一責任の原則違反です。別々の名前の関数に分割すること。
*   **❌ 出力引数の禁止:** メソッドの引数として渡したオブジェクトの中身を、メソッド内部で書き換えてはいけません。結果は戻り値として返すこと。
*   **❌ 貧血ドメインモデルの排除:** データ（Getter/Setterのみ）とロジックを別々のクラスに分離しないこと。データを持つクラス自身に、そのデータを使うロジックを持たせること。
